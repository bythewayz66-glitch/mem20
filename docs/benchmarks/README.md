## 1. Coverage: 11 declared modes, 7 scored

`mem20api` exposes seven read paths on `Store`. Four of them are measured by the
harness today; three are not. This table is the honest state of that coverage.
The artifact declares 11 modes because `bm25`, `hybrid-rerank-off` and
`constant` are scored configurations of those paths, not extra methods.

| # | Surface | Signature (`mem20api`) | Measures | Status |
|---|---|---|---:|---:|
| 1 | `recall()` | `recall(topic=None, tags=None, k=5, include_simulated=False)` | reverse-chronological filter by topic/tags | **not yet measured** |
| 2 | `recall_at()` | `recall_at(as_of, **kw)` | point-in-time recall — what was true at `as_of` | **not yet measured** |
| 3 | `semantic()` | `semantic(query, k=5, topic=None, tags=None, strict=False)` | vector search over MiniLM embeddings | measured |
| 4 | `hybrid()` | `hybrid(query, k=5, topic=None, tags=None, alpha=0.5)` | RRF fusion of vector + BM25, then rerank | measured |
| 5 | `graph()` | `graph(entity, hops=2, max_results=20, min_facts=1, topic=None)` | multi-hop entity/edge traversal | measured |
| 6 | `entities()` | `entities(limit=50)` | entity index listing by degree | **not yet measured** |
| 7 | `ledger()` | `ledger(k=20)` | write ledger tail | **not yet measured** |

`keyword` appears in the results below but is **not** a separate public method: the
harness isolates it by calling `hybrid(alpha=0.0)`, which is the shipped code path
for the BM25 half. That is the honest way to measure it — a private re-implementation
would be measuring something users cannot call.

### Why the gaps are real, not an oversight to paper over

`mem20benchmarkz/mem20benchmarkz/bench.py` implements exactly four branches in
`_run_mode()` — `semantic`, `hybrid`, `graph`, `keyword`. There is no call to
`store.recall()`, `store.recall_at()`, `store.entities()` or `store.ledger()`
anywhere in the harness. So the four unscored modes are not "missing data we
forgot to paste in"; they are surfaces the suite cannot currently score.
Filling them with estimates would be inventing a benchmark.

The artifact's own `mode_surface` block is the authority: **7 of 11 declared
modes scored, 4 unscored with a named blocker.** `benchmarks/results/latest.md`
renders that block verbatim.

`recall_at()` is the one worth prioritising: it is a distinct correctness axis
(point-in-time truth) that no other mode exercises.

## 7. What this table does not say

- **It is not a comparison to Mem0 or Zep.** See [`comparability-matrix.md`](comparability-matrix.md).
- **Every table above is the 2,000-record scale run.** The retired 13-query `mem20-agent-kb-v1` corpus is not in this repo; no row here comes from it.
- **`graph` carries a smaller `n`.** Only `multi_hop` probes carry an entity, so `graph` scores 30 of 250 probes — a corpus property, not a skip.
- **Latency is one machine.**

## 8. Reproduce

```bash
# small regression corpus
mem20benchmarkz run --out benchmarks/results
python docs/benchmarks/render.py
python docs/benchmarks/render.py --check

# scale corpus v2
mem20benchmarkz generate-scale --out /tmp/mem20-scale-corpus-v2
mem20benchmarkz run-scale --corpus /tmp/mem20-scale-corpus-v2 --bulk \
    --modes bm25,vector,hybrid,hybrid-rerank-off,graph,keyword,constant \
    --out benchmarks/results
```
