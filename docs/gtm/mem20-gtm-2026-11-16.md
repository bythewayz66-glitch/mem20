## 1. The one-paragraph position

mem20 is the **memory substrate for agents that must not confabulate**. It is an MCP server — JSON-RPC 2.0 over stdio — that gives an agent durable memory with a **hard partition between grounded and simulated recall, enforced at the storage layer rather than by prompt convention**. Try to write invented content through the grounded path and the server raises `PermissionError`; try to write a fact without declaring how it was learned and it raises `ValueError`. Every entry carries its origin and store in an append-only ledger, and `audit_contamination()` returns a contamination rate plus six violation classes for your store. It is **Apache-2.0**, Python 3.10+, self-hosted, and it exposes **487 tools across 129 domains** over MCP. You can read the code that holds your audit trail, because you cannot audit a black box.

**Category:** agent memory infrastructure.
**Wedge:** *auditable* agent memory — the memory layer you can prove.
**The sentence that must survive every edit:** *"Grounded vs simulated is a hard, audited boundary, not a prompt convention."*

## 3. The license correction — the repo is Apache-2.0, not MIT

**This is the single most important correction in this document.** Every v3-era GTM asset in this directory says **MIT**. The repository is **Apache-2.0**, and it has been since 2026-11-07.

| Source | Value | Command (settles it) |
|---|---|---|

| `README.md` | `- **License:** Apache-2.0` and `Apache License 2.0 — see LICENSE.` | `grep -n -i license README.md` |

| The relicense commit | `14e2ce0d 2026-11-07 chore: relicense to Apache License 2.0` | `git log --format='%h %ci %s' -- LICENSE` |

**What is still MIT, and must not be confused with the root license.** Three vendored sub-trees carry their own MIT `LICENSE` files: `mem20-sdk-ruby/LICENSE`, `teamz/LICENSE`, `web/LICENSE`. They are components inside the repo, not the repo's license. A GTM asset may say *"the Ruby SDK and the `teamz`/`web` components are MIT"*; it may **not** say *"mem20 is MIT"*.

**Why this matters commercially, not just legally.** The v3 wedge was *"MIT-licensed, self-hosted, zero lock-in."* Apache-2.0 preserves the two properties that wedge actually sold — **permissive, self-hostable, no copyleft, no lock-in** — and adds an explicit patent grant, which is *stronger* for the regulated buyers in Tier A. So the wedge survives; only the label changes. But a buyer who reads `LICENSE` after being told "MIT" has caught the seller in a false statement on the first page of the repo, and the entire trust position — which is the product — collapses. **Fix the label everywhere before the next launch asset ships.**

**Never say:** "MIT-licensed mem20", "MIT core", "MIT with an Apache appendix". Say: **"Apache-2.0 — permissive, self-hostable, no lock-in, with an explicit patent grant."**

## 4. The messaging hierarchy

**Level 1 — the category claim (what we are).**
> mem20 is the memory substrate for agents that must not confabulate.

**Level 2 — the wedge (why we win).**
> Grounded facts and simulated hypotheses live in separate stores, enforced at the storage layer. Not a flag. Not a prompt. A `PermissionError`.

**Level 3 — the proof (why you believe it).** Four artifacts, all in the repo, all runnable:

| Proof | What it shows | Command |
|---|---|---|
| The partition test | A grounded write succeeds; a simulated write through the grounded path is **refused**; `recall()` returns grounded only; `recall(include_simulated=True)` returns both; `audit_contamination()` returns `contamination_rate=0.0`, `status=CLEAN`, six violation classes all empty | `python3 docs/gtm/verify/partition.py` |
| The unlabeled-write guard | A fact with no declared `epistemic_status` is **refused** rather than stored | `python3 docs/gtm/verify/partition.py` → A7 |
| The promotion gate | Bare promotion refused; prediction-error promotion refused without a *recorded* prior prediction; free-text `confirmation` alone still promotes | `python3 docs/gtm/verify/partition.py` → PG1–PG6 |
| The benchmark | Seven retrieval modes scored on a 700-grounded / 1,300-simulated / 250-query corpus, **including the rows we lose** | `python3 docs/gtm/verify/bench_rows.py` |

**Level 4 — the surface (what you get).**
> 487 tools across 129 domains, over MCP JSON-RPC 2.0 on stdio. Apache-2.0. Python 3.10+. Self-hosted.

**Level 5 — the honest limits (why you trust levels 1–4).** Stated before the buyer finds them, every time:

1. **No LoCoMo / LongMemEval result is claimed.** The harness has not been run against the LoCoMo originals. `benchmarks/results/latest.json` says so in its own `notes` block.
2. **Sparse retrieval collapses on hard adversarial queries** — `bm25` 0.025, `keyword` 0.025 at n=40. Dense is materially better on the same class — `vector` 0.750, `hybrid-rerank-off` 0.625. The split *is* the finding; do not average it into one "adversarial score".
3. **Graph traversal is the weakest multi-hop mode** — `graph` 0.033 at n=30. Do not present graph as a strength.
4. **The promotion gate is narrowed, not closed.** A free-text `confirmation` argument still promotes (PG4). Say this before the buyer finds it.
5. **Install is source-only.** No PyPI package. `git clone` + `pip install -r requirements.txt`.

## 5. Differentiation — the one axis that matters

Every competitor in the developer-memory category competes on **retrieval quality**. mem20 competes on **provable separation**. That is the whole position, and it is defensible because it is a different axis, not a better score on the same one.

| Vendor | Architecture bet | Grounded/simulated split | Store-wide provenance ledger | Contamination metric published |
|---|---|---|---|---|
| **mem20** | Persistent memory + cognition substrate over MCP | **YES — enforced at the storage layer** | **YES — append-only, origin-tagged** | **YES — `contamination_rate`** |
| Mem0 | Passive LLM fact extraction into a vector store | no | no (per-record event history) | no |
| Zep / Graphiti | Bi-temporal knowledge graph; invalidate-not-delete | no | graph-native invalidation is the audit primitive | no |
| Letta (MemGPT) | LLM manages its own memory via tool calls | no | no | no |
| LangMem | Library bound to LangGraph agents | no | no | no |
| Cognee | Knowledge graph + vector over docs/code | provenance listed as Enterprise | no | no |
| Bedrock AgentCore / Vertex Agent Engine | Hyperscaler-embedded managed memory | no | CloudWatch / Cloud Logging adjacent | no |
| IBM watsonx.governance / ServiceNow AI Control Tower | Governance layer over what the agent **did** | no | governance-layer audit | no |

Source: `docs/market/competitive-matrix-2026-11-01.csv` (verified pricing, Oct 2026). **The gap is real and it is the only gap we sell:** governance tools log what the agent *did*; mem20 records what the agent *knows* and why it was permitted to know it. No competitor in the developer-memory category models epistemic status at write time.

**Never say:** "matches Mem0", "beats Zep", "industry-leading retrieval", "provably secure", "tamper-proof memory", "unfakeable". One of those in a deal and the trust position — which is the product — is gone.

## 6. Who this is for, and who it is not

| Tier | Segment | Trigger | Where they live |
|---|---|---|---|
| **A** | **Regulated AI teams** — fintech, healthcare, legal, gov | A model-risk or audit function asked *"where did the agent learn this?"* and the answer was *"the vector store"* | LinkedIn, industry conferences, direct outbound |
| **B** | **AI platform / infra engineers** building production agents | Their agent confabulated in staging and polluted the memory store | GitHub, HN, LangChain & MCP Discord, r/LocalLLaMA |
| **C** | **Self-host-first / OSS teams** and MCP-ecosystem builders | Cannot send memory to a vendor cloud | MCP directories, GitHub |

**Not a fit — say so early and save both sides the cycle:**
- Teams that only need retrieval relevance and have no audit obligation. Mem0 or a plain vector DB is cheaper.
- Teams that want a **managed SaaS with no operational surface**. mem20 is source-install and self-hosted; there is **no PyPI package and no hosted offering**. If they cannot run a Python service, the install is a blocker, not a feature.
- Teams needing a **published benchmark comparable to Mem0 or Zep**. We do not have one and will not claim one.
