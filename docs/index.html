The wedge

Not a retrieval-quality race. A trust and provenance race.

Every memory layer on the market competes on retrieval quality. None of them lead with auditability — the ability to show why a memory is in the store and where it came from. In a regulated context that is the whole ballgame: you don't need "probably relevant," you need "here is the source, and here is the evidence it was promoted."

01

Prove it, don't just retrieve it.

A hard grounded/simulated partition plus an append-only origin-tagged ledger tells you where every memory came from.

02

Catch contamination before it ships.

Auditing detects simulated content bleeding into grounded memory — leak rate 0.000 on clean stores.

03

Own your memory layer.

MIT licensed, Python, self-hosted. No lock-in, no black box, no vendor holding your audit trail.

Architecture

Two memory classes, one gate, and a ledger that keeps the receipts.

Grounded and simulated memory are separate stores, not labels on one store. Content crosses into grounded memory only through a promotion gate, and every crossing is written to an append-only, origin-tagged ledger. That is what makes the difference between "the model remembered something" and "here is the record of how it got there."

01

Grounded store

Verified facts. What an agent is allowed to treat as true, and what a reviewer can point at in an incident review.

02

Simulated store

Hypotheses, drafts and model-inferred content. Useful, never silently promoted, never mixed into grounded recall.

03

Promotion gate + ledger

Evidence-based promotion, and an append-only record of who wrote what, when, and on what grounds.

Read this before you read the table

These benchmarks are self-published on our own harness and describe this corpus only. mem20 does not have a published LoCoMo or LongMemEval result comparable to Mem0, Zep or Letta, so we make no parity claim and cite no one else's figure as ours.

The 0.000 adversarial hit rate is a genuine limitation, not a marketing footnote, and it is not confined to one mode: an adversary who knows how to phrase around the retrieval path defeats hybrid, keyword and semantic retrieval alike today. Retrieval runs at three different p50 latencies (0.6 ms graph, 12.2 ms semantic, ~104 ms with cross-encoder reranking on), and none of them buys adversarial robustness. If your threat model includes adversarial query injection, weigh that honestly before you deploy.

Straight talk

What we don't claim.

Three limits we'd rather state ourselves than have someone else discover in production.

No LoCoMo / LongMemEval result

mem20 has no published benchmark comparable to Mem0 or Zep. We do not imply parity, and we never present their numbers as ours.

Adversarial hit rate is 0.000

Hard adversarial queries defeat hybrid, keyword and semantic retrieval today. It's on the roadmap, and it stays visible wherever the benchmark table appears.

The promotion gate has known gaps

A self-attestation hole in the promotion gate was flagged in a prior audit. Promotion is auditable, with an append-only trail — not unfakeable, and not cryptographic.

Install

Run it on your own infrastructure.

If your memory layer is the thing you have to audit, you can't audit someone else's black box. mem20 is MIT-licensed and self-hosted by design — and not yet on PyPI, so install is from source.

shell 
# not on PyPI — install from source
git clone https://github.com/bythewayz66-glitch/mem20
cd mem20
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# run the MCP server over stdio (JSON-RPC 2.0)
MEM20_STORE_PATH=~/.mem20/store .venv/bin/python mcp/mcp_server.py
