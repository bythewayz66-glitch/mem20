auditable agent memory

A memory that can prove what it knows.

mem20 gives an agent something it does not otherwise have: a memory that survives the session, records why it believes what it believes, and can be audited after the fact. Grounded facts and simulated hypotheses never mix — and every retrieval reports its own drift.

FIG 01

The one rule

Most agent memory is a single undifferentiated pile: a guess and a fact look identical once they are both embedded. mem20 keeps them apart at the storage layer, so the distinction survives retrieval, summarisation and time.

✓

grounded What was observed

Written from a real event, a real document, a real tool result. Carries its provenance and can be re-checked against the source. This is the only class of memory mem20 will assert as true.

~

simulated What was inferred

Written by a model reasoning about what might be the case. Useful, and never presented as fact. It stays labelled, so a later reader — human or agent — can tell which is which.

FIG 03

Three layers, in dependency order

A durable substrate, a protocol surface, and a large estate of independently packaged capability modules.

01 Layer 01

Memory engine

Global memory, ledger and vector store. The durable substrate — everything else is a view onto it.

02 Layer 02

MCP server

Exposes the engine and the wider estate as 527 MCP tools over stdio, with an HTTP health/metrics endpoint.

03 Layer 03

Subsystems

135 domains of independently packaged capability, each with its own tool module and its own tests.

FIG 07

Run it

From a git checkout. The server starts, logs its health endpoint, and speaks JSON-RPC 2.0 over stdio.

bash
# clone and install
git clone https://github.com/bythewayz66-glitch/mem20.git
cd mem20
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# start the MCP server
MEM20_STORE_PATH="$HOME/.mem20/store" .venv/bin/python mcp/mcp_server.py

On the numbers. Every figure on this page is re-derivable. The tool and domain counts come from docs/surface.json, which is generated from the live tools/list response and checked in CI by the doc-count drift gate — a retired count in a live doc fails the build. The tiles, the big numbers and the largest-domains table on this page are also filled from docs/surface.json in the browser at load time, and the cross-check line above states the live pin on a single line so the gate can catch it if it ever goes stale again. README.md carries the same measurement alongside a table of corrections to numbers that were previously published and wrong. We would rather point you at the measurement than restate a claim here that we cannot re-derive.
