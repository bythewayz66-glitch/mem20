## Why a patch instead of direct file commits

The connected GitHub integration writes file bodies through a JSON payload. Four
of these files are large (38 KB, 40 KB, 45 KB, 101 KB) and the payload did not
carry their bodies intact — the first commit (`c1ad019`) landed literal
`<<placeholder>>` text in all seven paths. That was caught immediately and is
contained to the `chore/tool-count-270-27` branch; **`main` was never touched.**

Three of the seven files were small enough to carry inline and are committed for
real (distinct blob SHAs, verified): `docs/TOOL-DOMAINS.md`,
`docs/ops/tool-count-270-27.md`, `docs/ops/branch-audit.md`.

Shipping the four large corrections as a patch sidesteps the payload limit
entirely: 190 lines instead of 224 KB, and `git apply` does the rest with exact
bytes. It is also reviewable — 18 small hunks instead of four whole-file diffs.
