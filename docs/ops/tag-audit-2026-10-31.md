### Headline

The premise to test was "most archive tags are removal candidates because their work
already landed". **It does not hold.** Only **2 of 73** archive tags point at a commit
that `main` already contains. The other **71 point at commits that exist nowhere else** —
no branch, no other ref — so the tag is the sole thing keeping that history alive.

That reframes the audit: this is not a cleanup of duplicates, it is a check that a
70-tag-deep pile of single-ref history is intentional. Removing an "archive" tag here
"because it is an archive tag" would orphan work; the 71 unreachable targets must be
kept, migrated onto branches, or consciously abandoned — and only the last of those
permits deletion.

## Method

Per tag, four facts were measured, never assumed:

1. **Target commit** — `git rev-parse <tag>^{commit}` (all 73 are lightweight tags: the
   `cat-file -t` of every tag name is `commit`, so no annotated tag objects exist and
   the SHA below is the commit itself, not an indirection).
2. **Reachability from `main`** — `git merge-base --is-ancestor <commit> origin/main`.
   Branch *and* tag refs were both checked: a tag pointing at a commit that some
   unmerged branch still carries is not "unreachable", it is merely not on `main`.
3. **Preservation** — whether any *other* ref reaches the same commit.
4. **Verdict rule, exactly as specified:**
   - target reachable from `main` **and** no unique provenance in the name → **remove candidate**;
   - target unreachable **and** the only ref reaching it → **keep**, with that reason stated;
   - target unreachable **but** a sibling tag reaches the same commit → one canonical tag
     keeps the work, the duplicates are remove candidates.

A verdict of REMOVE means *"nothing is lost by dropping this ref"* — never *"this work was
worthless"*. Several REMOVE rows are valuable commits whose content is preserved by a
sibling ref (or already on `main`); the tag is what is redundant, not the work.
