## 1. What was broken

The Perl SDK was on `main` under `sdk/perl/**` and its test suite was green, but the
distribution **could not be packaged**. `make dist` failed outright:

```
Problem opening MANIFEST: No such file or directory at /usr/share/perl/5.36/ExtUtils/Manifest.pm line 349.
Could not add META.yml to MANIFEST: Could not open MANIFEST: No such file or directory
make: *** [Makefile:690: distmeta] Error 2
```

No `MANIFEST` means no tarball, and no tarball means nothing to upload to CPAN. The
distribution also lacked `LICENSE` and `Changes`, both of which PAUSE expects.

## 4. The CPAN path

### 4.1 Namespace status

`Mem20` is **unclaimed on CPAN** — `fastapi.metacpan.org/v1/module/Mem20` returns
`404`, as does `Mem20-Client`. The name is available, but it is not reserved: it
must be claimed through PAUSE before the first upload.

### 4.2 Steps to publish

1. **PAUSE account** — register at <https://pause.perl.org/pause/authenquery>.
   Registration is manually approved (typically 1–3 days).
2. **Claim the namespace** — request `Mem20` as a *new module* in PAUSE
   ("Request new module name"). Because the top-level `Mem20::` namespace is
   unclaimed, this is a first-come request; the SDK's 6 modules
   (`Mem20`, `Mem20::Client`, `Mem20::Config`, `Mem20::Errors`,
   `Mem20::Transport::Stdio`, `Mem20::Version`) should all be listed in one request.
3. **Upload** — once approved:
   ```bash
   cpanm --install Dist::Zilla   # not required; only for the uploader
   cpan-upload -u <PAUSE_ID> Mem20-0.2.0.tar.gz
   ```
   or via the PAUSE web form. `cpan-upload` ships with `CPAN::Uploader`
   (`cpanm CPAN::Uploader`).
4. **Indexing** — PAUSE indexes the dist within minutes; `cpanm Mem20` then works
   once the CPAN mirror nearest the user syncs (usually < 1 hour).

### 4.4 What cannot be done from this sandbox

The upload itself requires PAUSE credentials. No agent can complete step 3 without
them. Everything up to and including a verified, clean-room-tested tarball is done;
the remaining action is a human with a PAUSE account running `cpan-upload`.

## 6. Known upstream issues carried in the SDK

These are documented in `sdk/perl/AUDIT.md` and worked around in the client, not
patched upstream:

- **`serverInfo.version` is an empty string** in mem20 3.0.0. The live test asserts
  the empty string rather than pretending a version is there.
- **Three distinct failure shapes.** A tool can fail as a JSON-RPC error object, as
  `result.isError = true`, or — the dangerous one — as a protocol *success* whose
  text begins `Error`. The SDK maps all three to `Mem20::ToolError` and flags the
  third with `soft_error`, because a client trusting `isError` alone would report a
  dropped write as a stored fact.
- **`epistemic_status` is not enforced server-side.** `memory_store {}` silently
  stores an empty fact, so the SDK validates locally and raises
  `Mem20::ValidationError`.
- **`requirements.txt` omits `aiohttp`**, which `mcp/tools/a2a_tools.py` imports at
  module scope — the server will not boot without it.

MEM20_MCP_DIR=<repo>/mem20_mcp MEM20_PYTHON=python3 \
  prove -Ilib sdk/perl/t/90-live-server.t
