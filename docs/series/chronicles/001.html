Origin: grounded. This installment reports what the repository actually did in its window. Every figure in it was measured against the tree, and the chapter names the file or command it came from. Where it could not stand behind something, it says so in its own text rather than smoothing it over.

One unit needed correcting, and it is the subtlest number in this document. The brief says "177 at-risk commits". That figure reproduces exactly — 177 is the sum of every branch's ahead-count —

$ tot=0; for b in $(git for-each-ref --format='%(refname:short)' refs/remotes/origin \
      | grep -v 'origin/HEAD' | grep -v '^origin/main$'); do
    tot=$((tot + $(git rev-list --count origin/main..$b))); done; echo $tot
177

— but a commit that sits on three branches is counted three times by that loop, and when you ask how many distinct commits are stranded the answer is 168. Both numbers are right, they answer different questions, and §5 is about the nine-commit difference because that difference is the most interesting fact in the round.

The frontier moved while this document was being written

The reconciliation above is against the brief's baseline, 45445f48. That baseline was correct when the brief was written and it is no longer the tip of main, because a second merge landed during this run. The merge is e7758bd178d38da63c5359dded0aada8bfc0eea5, subject Merge content/ws3-investor-deck into main (2026-10-27 convergence), and its diffstat is 16 files, +1,251, −0 — which is exactly the diffstat §4 records for the content/ws3-investor-deck branch. So the second landing of the round is that branch, and it is a merge commit, not a squash: the branch's four commits are now reachable from main and its tip 75243c4c6dd53998af2f45b17333a7aa8997c984 is an ancestor.

This changes the round's headline in one specific way and leaves it intact in another. Two commits from the round reached main, not one — the roster as squash 45445f48, and the investor deck as merge e7758bd. The at-risk figure falls from 177 to 173. What does not change is the shape: 21 of 22 agents delivered a branch, and the overwhelming majority of the round's work — 173 branch-commit slots, 164 distinct commits — is still outside main.

Every figure in §3, §4 and §5 is stated against the brief's baseline 45445f48, because that is the baseline the round was dispatched against and the one the brief named. Where a reader wants the publication-time figure, this table supplies it. A count is a fact about the moment it ran, and this document ran across two moments; saying so is cheaper and more honest than picking one.

None of these is an error in the roster. Each was true at 08:44Z. The roster's 29 branches is particularly instructive: the roster is one of the twenty-three branches that invalidated its own count, because committing the roster created docs/ws1-workload-roster-2026-10-27. A count in a moving tree is a fact about the moment it ran. This is not a criticism of the roster; it is the roster's own doctrine, applied to the roster.

The figure this document still will not claim

270 tools across 27 domains is the project's authoritative surface figure. It was not re-derived by instantiating the server in this run, because the sandbox has no mcp package:

$ cd mcp && python3 -c "from server import Mem20MCPServer; print(len(Mem20MCPServer().tools))"
Error: mcp package not installed. Please install with:
pip install mcp

What was checked is that the figure is the repository's declared authority, recorded with its own provenance line in docs/finance/inputs.json:

"tools": 270, "domains": 27,
"previous_tools": 257, "previous_domains": 26,
"authority": "verify_mcp.py MEM20_EXPECTED_TOOLS default = 270 (instantiates Mem20MCPServer,
counts server.tools); CI .github/workflows/mcp-verify.yml pins 270; ..."

So the sentence this document may write is "the repository states 270/27 and names the method that produced it"; the sentence it may not write is "the server registers 270 tools". The gap between those two sentences is the whole discipline, and it is why the roster's row 10 — assigned to GitHub Repo Assistant — asks for a collected count rather than a passed count.

Note also that the authority record keeps the retired values, 257 and 26, as prior values rather than deleting them. That is the same instinct as an append-only ledger, and it is the reason PR #118's body can say collected 2486 → 2489 and have both halves be checkable.
