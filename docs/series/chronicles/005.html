One hundred and seventy-seven, one hundred and sixty-eight, one hundred and eighty-three

2026-10-27 grounded 875 words
All installments RSS

Origin: grounded. This installment reports what the repository actually did in its window. Every figure in it was measured against the tree, and the chapter names the file or command it came from. Where it could not stand behind something, it says so in its own text rather than smoothing it over.

The brief for this document says "177 at-risk commits". That number reproduces. It is also the wrong number to put in a headline, and the reason is worth three commands.

$ git rev-list --count --all --not origin/main
183
$ RT=$(git for-each-ref --format='%(refname)' refs/remotes | grep -v 'origin/HEAD' \
        | grep -v 'origin/main$' | tr '\n' ' ')
$ git rev-list --count $RT --not origin/main
168
$ tot=0; for b in $(git for-each-ref --format='%(refname:short)' refs/remotes/origin \
        | grep -v 'origin/HEAD' | grep -v '^origin/main$'); do
      tot=$((tot + $(git rev-list --count origin/main..$b))); done; echo $tot
177

Three numbers, one repository, one moment. The decomposition:

FigureWhat it countsHow
183every commit on any ref — branches and tags and stashes — not reachable from maingit rev-list --count --all --not origin/main
177the sum of each branch's ahead-count, so shared commits are counted once per branchloop over refs/remotes/origin
168the union — distinct commits on remote branches, not reachable from maingit rev-list --count $RT --not origin/main

The gap between 177 and 168 is nine, and it is exactly the nine duplicate-counted commits:

unique: 168
commits on >1 branch: 8   -> extra count: 9

Six of the eight are the Perl SDK commits that fix/ws2-perl-jobs-coverage inherited from fix/perl-sdk-270-surface. One is the offline-lifecycle commit fix/39-offline-degraded-ux that feat/38-command-palette was built on top of. One — fc8e0a440, the Telegram turnstile test — appears on three branches: fix/43-telegram-turnstile-proof where it was written, and then on both command-palette and offline-degraded, which were cut from that tip.

And the gap between 177 and 183 is six, which is the ref-namespace difference: --all includes refs/tags/, and this repository has fifteen tags, of which the archive- family preserves branch tips as tags precisely so that deleting a branch loses nothing. A tag pointing at a commit that a branch also contains contributes zero new commits to the union — which is why 183 − 168 = 15 does not equal the tag count either. The --all figure is a superset of the branch union and a disjoint* reading of any per-branch sum.

What broke. This is the third time in this serial's short life that a commit count has been mis-stated by a unit error, and it is the subtlest instance yet. The earlier two were: a hand-summed headline of 263 against subtotals of 212 (§6.3), and a per-day count taken on the wrong clock. This one is different in kind. Every one of 177, 168 and 183 is correctly computed by the command beside it. None of them is wrong. The error is in the sentence built on top, which says "177 commits are at risk" when it should say "177 branch-commit slots, 168 distinct commits".

The specific mechanism that makes it easy: the brief supplied 177, the number reproduced exactly, and a figure that reproduces feels verified. It is verified — as a sum. The verification confirmed the arithmetic and left the unit unexamined, which is the comfortable failure mode. A number that reproduces is verified only in the sense in which it was computed.

What we learned. Three questions, asked in this order, settle any "N commits at risk" claim:

git rev-list --count --all --not main              # every ref, incl. tags
git rev-list --count <branch-refs> --not main      # distinct commits on branches
# and then: does the per-branch sum equal the union? If not, work is shared.

If the sum exceeds the union, some commits are on multiple branches and the difference is the amount of duplication. That difference is not noise — it is a map of which branches were stacked rather than forked, and in this round it is the direct fingerprint of the roster's own "do not duplicate" instructions. The duplicate count is the evidence that the anti-duplication instructions worked.

And the corollary that saves the next census from over-reporting: one of the 177 is 05da846, whose content is already on main as squash 45445f48 (§3). So the honest at-risk figure is 168 distinct commits on 51 branches, of which at least one is a squash twin of landed work — and the exact number of remaining genuine risk requires a blob comparison per squash-merged branch, which this document has not performed for all 51 and therefore does not claim.
