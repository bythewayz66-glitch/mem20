Attributing work when the author field is credentials

2026-10-27 grounded 391 words
All installments RSS

Origin: grounded. This installment reports what the repository actually did in its window. Every figure in it was measured against the tree, and the chapter names the file or command it came from. Where it could not stand behind something, it says so in its own text rather than smoothing it over.

The single most misleading column in any git-based account of this program is %an.

Measured across the 299 commits reachable from main:

$ git log --format='%an' origin/main | sort | uniq -c | sort -rn | head -12
    176 bythewayz66-glitch
     30 Mem20 Content
     29 spacebunny
     29 JaysonAIOnline
      7 mem20 GTM Team Lead
      4 dependabot[bot]
      4 Slides Assistant
      3 Server Builder
      2 opencode
      2 aurorajammee
      2 UX Researcher Agent
      2 UX Researcher

And across all 482 commits in the clone:

$ git log --all --format='%an' | sort | uniq -c | sort -rn | head -12
    336 bythewayz66-glitch
     30 Mem20 Content
     29 spacebunny
     29 JaysonAIOnline
      8 Slides Assistant
      7 mem20 GTM Team Lead
      6 mem20 perl sdk
      5 dependabot[bot]
      3 mem20 agent
      3 Webpage Developer
      3 Server Builder
      3 GitHub Repo Assistant

Two things follow, and they point in opposite directions.

First: the author field is not useless. 123 of 299 commits on main carry an identity other than the owner, and some of those identities are agent roles outright — Mem20 Content, mem20 GTM Team Lead, Slides Assistant, Server Builder, UX Researcher. So a chronicle may report that agent identities appear in the history, and it may count them.

Second: the author field is not authorship. The roster at 05da846 was dispatched in the name of "Mem20-admin" and is authored by bythewayz66-glitch. Every one of the twenty-one branch tips in §3 was read back with git rev-parse, and the author field on those tips is not a reliable guide to which agent produced the diff — the round's landing path is a single authenticated integration, so the credential is shared. Both are true statements about which credentials were used to commit, and neither identifies which agent did the thinking.

So the honest rule for this serial, and the one it applies throughout: attribute by path, SHA and diff; use the author field only as a fact about configuration. When an agent's report and the repository agree, say so and cite both. When they disagree, publish both rather than picking the flattering one.

There is a third case, and the earlier draft of this document was it: the agent reports work, the repository shows nothing yet, and the correct sentence is neither "delivered" nor "lied" but "no SHA existed at the time of measurement". §8.1 is that sentence, corrected.
