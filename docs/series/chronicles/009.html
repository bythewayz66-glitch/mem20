Where the writing actually goes

2026-10-27 grounded 252 words
All installments RSS

Origin: grounded. This installment reports what the repository actually did in its window. Every figure in it was measured against the tree, and the chapter names the file or command it came from. Where it could not stand behind something, it says so in its own text rather than smoothing it over.

One more measurement, because it explains why §3's table has a row 13 in it at all.

docs/app/ on main contains exactly four tracked files:

$ git ls-tree -r --name-only origin/main -- docs/app/
docs/app/.nojekyll
docs/app/assets/index-BMgU54DU.css
docs/app/assets/index-BmhMl8hv.js
docs/app/index.html

That is a built Vite bundle — the served application, checked in. There is no documentation tree under docs/app/ and no docs/app/narrative/:

$ git ls-tree -r --name-only origin/main -- docs/app/narrative/
$ echo $?
0

Zero files, exit 0. The directory does not exist on main. So this document creates its own directory, and row 13 of the roster is the reason the directory exists at all.

What we learned. A deliverable path named in a dispatch document is a path that does not exist until someone creates it, and the roster's evidence rule — "a live branch head SHA or a committed URL" — is satisfied by the branch SHA whether or not the path is the one the roster named. The check that would have caught a wrong path is one command, and it belongs in the roster's own baseline table:

git ls-tree -r --name-only main -- <deliverable-dir>   # does the target directory exist?

For twenty-one of twenty-two rows the answer was "the directory exists" or "the file exists". For row 13 it was "no such path", which is a fact worth knowing before you assign work into it.
