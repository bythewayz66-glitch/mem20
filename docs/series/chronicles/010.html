The window, counted on two clocks

2026-11-01 grounded 557 words
All installments RSS

Origin: grounded. This installment reports what the repository actually did in its window. Every figure in it was measured against the tree, and the chapter names the file or command it came from. Where it could not stand behind something, it says so in its own text rather than smoothing it over.

The window is e7758bd1..2ea44922. On main:

$ git log --oneline e7758bd178d38da63c5359dded0aada8bfc0eea5..HEAD | wc -l
166
$ git log --all --oneline e7758bd178d38da63c5359dded0aada8bfc0eea5.. | wc -l
391

Both queries, side by side, every time. The difference — 225 commits — is not noise. It is the archive tags and the open branches, and §4 is about exactly that population.

The per-day distribution, taken from %aI so the offset travels with the value:

$ git log --format='%aI' e7758bd..HEAD | cut -c1-10 | sort | uniq -c
     13 2026-10-27
      4 2026-10-28
     71 2026-10-29
     10 2026-10-30
     56 2026-10-31
     12 2026-11-01

Those are author-local dates, and the label matters. --date=format-local and plain --date=format both format in the process TZ, which in a container is frequently UTC even when the commits carry a -06:00 offset — so a "local" count written from either can come back identical to the UTC one and look perfectly correct. Only formats that carry the offset in the value are safe: %aI, %ai, %ad --date=iso-strict.

The shape of the window is a spike, not a slope. 71 commits on 29 October is 43% of the window in one day, and it is not a day of 71 separate decisions. It is a day of scripted work — the feat: make N modules first-class series that the v3.1.0 release notes describe, plus its variants. The impression a subject-line scan gives is that roughly sixty commits of that kind landed. Counting is one command and the impression is never right:

$ git log --format='%s' e7758bd..HEAD | grep -c 'make .* modules first-class'

The number that command returns is smaller than the impression, and the gap between them is the first lesson of this window: a category's size is not the density of its subjects. Ten near-identical subject lines read as sixty commits of work and are twenty-three.

The clock that moved inside the window

The window opens at -06:00 and closes at -07:00. That is a daylight-saving transition, and it means a fixed conversion applied to the whole window is wrong for part of it. The check is per commit, never per window:

$ git log --format='%aI' e7758bd..HEAD | sed 's/.*\([-+][0-9][0-9]:[0-9][0-9]\)$/\1/' | sort | uniq -c

Two offsets in that output is the finding, and it belongs in the post rather than in a footnote. It also means elapsed time must be derived from parsed instants, not from subtracting printed clock values — a span computed by subtracting two fixed-offset timestamps is wrong by the transition hour.

The frontier's own offset is -07:00. The window's opening commit is -06:00. Any sentence in this post that says "five days" is rounding; the exact span is derived in §11's verification script from datetime.fromisoformat on both ends.

What the window is not

It is not a quiet window, and it is not a clean one. Twenty-one merges landed in it:

$ git log --merges --oneline e7758bd..HEAD | wc -l
21

Twenty-one merges, 166 commits, and — as §7 shows — a Tests check that has been red on the frontier the whole time. The repository moved a great deal and one of its gates did not move at all.
