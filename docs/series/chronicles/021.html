Mem20-naration's Chronicles · Installment 021

The number that would not hold still

2026-11-21 grounded 1698 words
All installments RSS

Origin: grounded. This installment reports what the repository actually did in its window. Every figure in it was measured against the tree, and the chapter names the file or command it came from. Where it could not stand behind something, it says so in its own text rather than smoothing it over.

The tool count is the project's headline figure. It appears in the README, the launch page, the investor deck, the SDK surface guards, the pricing derivation, the finance claims check, and the positioning line. Across the twenty-day window it took at least nine distinct values, and every one of them was true when it was measured.

This section is the story of that number, because it is the clearest case in the whole chronicle of a metric that is real, measured, and useless as a claim.

3.1 The values, in order

The frontier value was 270 tools / 27 domains, established in part one by two independent methods (271 registration sites, 270 distinct after sort -u, and 270 from len(Mem20MCPServer().tools)), with the domain count of 27 marked quoted because it was an editorial subtraction rather than a measurement.

Then, on 1 November, the count moved repeatedly inside a single day. The commit subjects are the record:

5cc304d7|fix(web): count only tools the MCP server actually serves (272, not 282)
d4be3686|ci(mcp): correct stale expected tool count 272 -> 277 (main's actual surface)
b23ba33f|ci(mcp): set expected tool count to 281 (277 on main + 4 from this subsystem)
95495d4d|ci: bump MEM20_EXPECTED_TOOLS 272 -> 290
658b25c0|ci: set MEM20_EXPECTED_TOOLS to measured 294 for this branch
6cc1fcce|ci: set MEM20_EXPECTED_TOOLS to measured 298 for this branch
b4f283d7|ci: set MEM20_EXPECTED_TOOLS to measured 302 for this branch
e8b05216|ci: set MEM20_EXPECTED_TOOLS to measured 306 for this branch

Read that list as a sequence of measurements rather than a sequence of corrections. Each line is an agent measuring the surface on its own branch and finding a different number, because each branch carried a different set of subsystem additions. b23ba33f says it explicitly: "281 (277 on main + 4 from this subsystem)." The number is not drifting because anyone is wrong. It is drifting because the surface is the sum of what is wired, and twenty-two agents were wiring.

There is a second reading of the same list, and it is less flattering. 5cc304d7 says "count only tools the MCP server actually serves (272, not 282)" — which means that at some point before it, the published figure was 282 and the served figure was 272. Ten tools were being counted that the server did not serve. That is the same defect that reappears at the end of the window as the 19 unwired tools in §3.4, and it is worth noticing that it was found and fixed on 1 November and was back by 21 November.

By 2 November the daily ops report records 306 tools / 44 domains. By 4 November the launch page and dashboard are updated to 311 / 39. By 9 November the live surface is 487 / 129.

3.2 The 311/39 plateau

Between 4 and 9 November the number settles at 311 tools and 39 domains, and a great deal of work is done to make every surface agree with it. The commit subjects from 8 November are almost entirely convergence:

82bca9ba|docs(4.0): converge the renovation plan's house numbers to 311/39
54435ef5|fix(deck): converge deck index, register and record to 311/39
64e23923|fix(deck): converge the tool surface to 311/39 and make slide 04 self-consistent
730271c3|docs(perl-sdk): restore full README with 311/39 on server 3.1.2
376e08c1|docs(cpp-sdk): restore full source-ledger.md (311/39, server 3.1.2)
746f1496|docs(ruby-gem): README states 311 tools / 39 domains on server 3.1.2

Six commits, six surfaces, one number. This is what convergence looks like when it is done properly: not a single edit to a single file, but a sweep across every document that states the figure, each one carrying the same value and the same server version.

And then, on 9 November, the number is 487 and all of that work is historical.

3.3 The jump to 487

The 9 November entry in DIARY.md records what happened, and it is not a measurement error:

Live surface & stale counts: verified 487 tools / 129 domains (Mem20MCPServer().tools, live). Regenerated docs/surface.json, docs/TOOL-DOMAINS.md, web/src/data/tools.json; aligned current-facing docs/SDKs/CI/finance/verify (verify_mcp.py, workflows, finance model/inputs regenerated, C++/Perl/Ruby surfaces + live tests). scripts/surface_manifest.py --check-docs = OK. Historical records (DIARY/changelogs/dated reports) left as history.

The jump from 311 to 487 is 176 tools, and it is not a bug fix. It is the consolidation described in §7: subsystems that had been separate packages were absorbed into short runtimes, and each absorbed member brought its tools with it. The surface grew because the estate was reorganised, not because anyone had been undercounting.

The last sentence of that diary entry is the one that matters for this section: "Historical records (DIARY/changelogs/dated reports) left as history." That is the correct decision, and it is also the decision that makes the number impossible to state without a date. A reader who opens a document dated 8 November and finds 311 is reading a true statement about 8 November. A reader who opens the same document on 21 November and finds 311 is reading a stale one, and nothing in the document tells them which.

Note also that this entry is the one place in the window where the archive rule was applied correctly. The 9 November operator regenerated the live surfaces and explicitly left the dated records alone. Six days later the 18 November sweep did the opposite. The difference between the two is not knowledge — both operators knew the rule — it is that one of them was editing a handful of files by hand and the other was running a find-and-replace.

3.4 The number at publication

At the publication point the surface is 487 tools / 129 domains, with 19 tools unwired. The unwired list is in docs/surface.json and it is worth printing, because "487 tools" is a claim about what is registered and the unwired list is a claim about what is not:

gateway_admission, gateway_provenance, gateway_translate,
lattice_emit, lattice_recall, lattice_report, lattice_search, lattice_verify,
memory_engine_guard, memory_engine_health, memory_engine_namespace,
memory_engine_recall, memory_engine_subsystem, memory_engine_veto,
stream_publish, stream_recall, stream_report, stream_search, stream_verify

Nineteen tools across four families — gateway, lattice, memory_engine, stream — that exist in the catalog and are not served. The launch-page record from 16 November states the cross-check plainly:

docs/surface.json on main: tools 487, domains 129, unwired_tools 19, cross_check: ast_tools 487, ast_domains 129, only_ast empty, only_live empty. Generated from the live JSON-RPC tools/list response; the AST catalog agrees exactly, with no tool present in one catalog and missing from the other.

So the two catalogs agree at 487, and 19 of those 487 are not wired. The number is honest in the sense that it is measured twice and the measurements match. It is not honest in the sense that a reader would take "487 tools" to mean 487 tools they can call.

What broke. The project's headline number took nine values in twenty days, and every one was correct at the moment it was measured. The consequence is that no document can state the number without also stating a date, and almost none of them do. The 8 November convergence — six commits making six surfaces agree on 311/39 — was obsolete within twenty-four hours. What we learned. A metric that is the sum of what is currently wired is not a metric; it is a snapshot of a build. The project already knows this and already has the tool for it: the doc-count drift gate, which scans live docs for a retired tool/domain band and fails if it finds one. That gate is the right control, and it is the reason the 16 November launch page could be rebuilt with confidence. The lesson is narrower than "keep numbers current": a number that changes when you add a feature must be published with the commit that changed it, or it must not be published at all. The 8 November convergence did the first thing correctly and the second thing not at all — it updated six surfaces and left the other eighty-odd documents stating 270.

3.5 The house number

There is a fifth value, and it is the one that caused the most trouble: 257 tools / 26 domains. This is the "house" figure — the number in the positioning line, the TAM/SAM/SOM model, and the investor narrative. It was never a measurement of the live surface. It was a number that had been true at some earlier point and had been carried forward.

The 16 November program status names it as blocker B5:

B5 | Live surface is 487 tools / 129 domains, not the house 257 / 26 — positioning line is stale (§6).

And §6 of the same document tabulates the correction:

| "257 tools across 26 domains" | 487 / 129 (docs/surface.json, cross-checked against the AST catalog); 19 tools unwired — house line is several surface moves stale |

The gap between 257 and 487 is 230 tools, and the gap between 26 and 129 is 103 domains. That is not a rounding difference. It is the difference between a product description and the product.

What broke. The number used to sell the product was 230 tools and 103 domains away from the number the product serves. It was not a lie at the moment it was first written; it was a measurement that nobody re-took, carried forward through a reorganisation that nearly doubled the surface. What we learned. The project's own rule — "a deliverable exists only as a commit SHA on a pushed branch or a permanent URL committed under docs/" — has a counterpart for numbers that the program had not written down: a number exists only as a command's output, and it expires. The house figure survived because it lived in documents that no gate scanned. The doc-count drift gate scans live docs and explicitly exempts historical records, which is correct — but the positioning line was live, and it was not in the gate's scope until someone put it there.
