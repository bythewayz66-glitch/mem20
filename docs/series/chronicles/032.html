The gate that was never built: dated-record exclusion

2026-11-21 grounded 1374 words
All installments RSS

Origin: grounded. This installment reports what the repository actually did in its window. Every figure in it was measured against the tree, and the chapter names the file or command it came from. Where it could not stand behind something, it says so in its own text rather than smoothing it over.

The second open question was whether anything prevents a dated record from being rewritten after publication. The previous instalment had found two cases where it happened. The question is whether a gate exists that would catch the next one.

The answer is again no, but the trail is more interesting, because there is a rule, written down, in two places, and there is a fix that was applied to the wrong layer.

4.1 The rule, as written

scripts/sweep-tool-counts.py carries this docstring:

Append-only / dated records keep their historical numbers, because rewriting
them would falsify the record rather than correct it:

  CHANGELOG.md                  history of earlier reconciles
  published/**                  immutable delivery archive (MANIFEST-pinned)
  published/daily-reports/*.md  dated ops logs
  docs/audit/*.md               dated audits
  docs/recon/**                 the stale-file inventory and its evidence
  docs/ops/metrics.json         dated issue titles / branch names
  .sitemap/sitemap.json         generated snapshot
  toolchest/inventory.json      generated snapshot
  **/*.patch, bench/optionc     captured diffs of past states
  "older docs quote 258-260"    sentences that describe the retired value

That is a correct and complete statement of the rule. It is also, as the commit that added half of it says, a statement the code did not implement.

4.2 The fix that came too late

0eab51ad, 7 November 2026, subject "fix(sweep): stop rewriting the immutable archive and dated records":

The sweep's own docstring says append-only records keep their historical
numbers, but its skip list was incomplete: it rewrote published/** (breaking
published/MANIFEST.tsv, which has no generator in the repo), .sitemap/,
docs/ops/metrics.json (dated issue titles) and the recon inventory's own
evidence strings. Add them to the skip list and mirror the new allowlist
entries in the inventory generator.

Two files changed, 26 insertions and 1 deletion. The diff adds published/ and docs/recon/ to SKIP_PREFIXES, and four paths to SKIP_FILES:

+    ".sitemap/sitemap.json",                            # generated snapshot
+    "docs/ops/metrics.json",                            # dated issue titles / branch names
+    "docs/recon/stale-file-inventory-2026-11-07.json",  # inventory evidence strings
+    "toolchest/inventory.json",                         # generated snapshot (306 entries)

And the comment above the prefix list:

+    # published/ is the immutable delivery archive, integrity-pinned by
+    # published/MANIFEST.tsv (per-file sha-256) and governed by
+    # published/README.md rule 3 ("never edit a preserved file in place").
+    # There is no manifest generator in the repo, so rewriting a preserved file
+    # breaks the manifest permanently. The sweep must not touch it.
+    "published/",

Every sentence of that comment is true. published/ is the immutable archive. It is pinned by MANIFEST.tsv. Rule 3 of published/README.md says never edit a preserved file in place. And rewriting a preserved file does break the manifest.

The comment also contains a claim that is false: "There is no manifest generator in the repo." There is one. scripts/gen_manifest.py exists, has a --check mode, and its docstring says:

The manifest is a claim: for every file under published/, this many bytes and
this SHA-256. It was maintained by hand, and by 2026-11-01 thirty-two of its
128 rows were wrong -- unchanged across four separate measurements, because
nothing regenerated it and nothing checked it.

This script is both halves:

    python3 scripts/gen_manifest.py            # rewrite the manifest
    python3 scripts/gen_manifest.py --check    # exit 1 if any row is wrong

So the fix was written on a false premise — that the manifest could not be regenerated, and therefore that any edit to published/ was permanent damage. The premise was wrong, but the conclusion was right: the sweep should not touch the archive. A correct rule resting on an incorrect reason is still a correct rule, and it is also a rule that will be re-litigated by the next person who reads the comment and discovers the generator exists.

4.3 The fix did not prevent the next rewrite

0eab51ad landed on 7 November. The 18 November sweep (0cd80344) rewrote four dated records anyway.

The reason is visible in the repository and it is not a bug in the skip list. scripts/sweep-tool-counts.py is not invoked by any workflow. grep -rn 'sweep-tool-counts\|stale-file-inventory' .github/workflows/ returns nothing. The script is a tool a human runs by hand, and the 18 November commit was not that script running — it was a hand-run find-and-replace across the working tree, with a commit subject that says so: "Replace 3.1.2 with 4.0.0 across repository and include pending workspace changes".

A skip list protects against the tool that reads it. It does not protect against a different tool, or against a human with sed.

4.4 The other half of the rule

scripts/ops/check-doc-counts.py is the one gate in the repository that explicitly reasons about dated records. Its exclusion list:

EXCLUDE_PREFIXES = (
    "published/",          # immutable delivery archive (MANIFEST-pinned)
    "docs/audit/",         # dated audits
    "docs/recon/",         # stale-file inventory + evidence
    "docs/ops/",           # dated ops logs
    "docs/app/narrative/", # dated serials
    "docs/app/deck/",      # dated deck records
    "docs/renovation/",    # in-flight 4.0 overhaul
    "ops/",                # dated ops records
    ".sitemap/",           # generated snapshot
)
EXCLUDE_FILES = {
    "CHANGELOG.md",        # history of earlier reconciles
    "DIARY.md",            # dated diary
    "failures.md",         # dated failure log
    "AbsoluteTruth113.md", # dated audit narrative
    "toolchest/inventory.json",  # generated snapshot
}

This is the most complete statement of the dated-record rule in the repository, and it is correct. The gate excludes every dated record from its scan, because a dated record is allowed to contain a retired number — that is what makes it a record.

But exclusion from a count check is not protection from a rewrite. The gate's purpose is to fail when a live doc carries a retired tool count. It says nothing about whether a dated doc has been altered. A dated record could be rewritten from top to bottom and check-doc-counts.py would pass, because it never looks at it.

Running it confirms the gate works as designed:

$ python3 scripts/ops/check-doc-counts.py --self-test
SELF-TEST OK: 5 seeded line(s) caught, 4 clean line(s) passed

$ python3 scripts/ops/check-doc-counts.py
live pin: 487 tools / 129 domains
scanned: 85 live doc(s)
OK: no retired tool/domain band in any live doc

Eighty-five live docs scanned, zero violations. The gate is healthy. It is also, by construction, blind to the exact failure the previous instalment documented.

4.5 The verdict

No dated-record-exclusion gate exists. What exists is:

  • a skip list in scripts/sweep-tool-counts.py, which is not invoked by CI and which protects only

against that one script;

  • an exclusion list in scripts/ops/check-doc-counts.py, which correctly excludes dated records from a

count check and therefore cannot detect their alteration;

  • a --check mode in scripts/gen_manifest.py that would detect byte changes under published/, and

which is not invoked by any workflow.

The third is the closest thing to a real gate, and it is not wired up. Running it by hand:

$ python3 scripts/gen_manifest.py --check
  MISMATCH published/README.md
  MISMATCH .../mem20-ruby-sdk/CHANGELOG.md
  ... (10 total)
  UNLISTED published/checkpoints/ledger.md
  ... (10 total)
::error::published/MANIFEST.tsv does not describe the tree

Ten mismatches, ten unlisted files, 129 manifest rows against 172 files present. The archive's integrity claim has been false for some time, and the only tool that can say so is not run automatically.

What broke. A rule was written down in a docstring, implemented in a skip list, and then bypassed by a different tool. A second gate excluded dated records from its scan for the right reason and thereby became incapable of noticing their alteration. A third tool could have caught it and was never wired up.

What we learned. A skip list is a promise a tool makes to itself. It is not a gate. The only thing that would catch a rewrite of a dated record is a check that compares the record against the commit that first published it — git diff $(git log --diff-filter=A --format=%H -- "$f" | tail -1) HEAD -- "$f" — and no such check exists in this repository. The audit in §5 is that check, run by hand, once.
