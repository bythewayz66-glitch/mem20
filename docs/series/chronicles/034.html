The archive's integrity claim is false

2026-11-21 grounded 800 words
All installments RSS

Origin: grounded. This installment reports what the repository actually did in its window. Every figure in it was measured against the tree, and the chapter names the file or command it came from. Where it could not stand behind something, it says so in its own text rather than smoothing it over.

published/MANIFEST.tsv is the archive's own claim about itself: for every file under published/, a byte count and a SHA-256. It is the mechanism by which the archive can say "this file has not been altered" without anyone having to trust a human.

::error::published/MANIFEST.tsv does not describe the tree

Ten mismatches, ten unlisted files. 129 manifest rows against 172 files present.

6.1 What the mismatches are

Most of them are the 22 October tool-count sweep. 2960e662, subject "Fix #81: update stale 257-tool claim to 268 (#89)", touched five of the ten:

  • .../mem20-ruby-sdk/CHANGELOG.md — 257 registered tools → 268 registered tools
  • .../mem20-ruby-sdk/EVIDENCE.md — the same substitution in two places
  • .../mem20-ruby-sdk/README.md — 257 tools → 268 tools in two places
  • .../sidney-mem20-deploy-credential-update/DEPLOY_REPORT.md — /ready -> {"ready": true, "tools": 257} → 268, and 257 tools across 26 domains → 268 tools across 26 domains
  • .../mem20-design-research/README.md — five lines
  • .../mem20-market-research-v3/gabe-bundle/PUBLISH-RUNBOOK.md — 257 headline → 268 headline

That is a tool-count sweep rewriting preserved files in place. It is the exact act published/README.md rule 3 forbids: "Never edit a preserved file in place. This is an archive."

Two more are the 26 October frontend copy sweep: d27fcef0 on the canonical-url-audit page and 269cd042 on the repo_v3 cover slide. Both changed 257 tools / 26 domains to 270 tools / 27 domains inside a published artifact.

One is a content restore: cd13951a, "restore: real content for mem20-asset-refresh-report.md", following 0d4af6a3 which had clobbered seven assets with a placeholder payload.

6.2 The unlisted files

Ten files exist under published/ with no manifest row at all. Nine of them are the entire published/content/mem20-long-form-v3/ directory — the long-form copy assets, added after the manifest was last regenerated. One is published/checkpoints/ledger.md and its generator.

So the manifest does not describe the tree in two directions: it has rows for files whose bytes have changed, and it has no rows for files that exist.

6.3 Why this matters more than it looks

The manifest is the archive's only self-verification mechanism. published/README.md rule 4 states the law: "Verify with hashes, not prose. MANIFEST.tsv is authoritative; a file whose SHA-256 does not match the manifest has been corrupted or changed."

That rule is correct, and it is currently unenforceable, because the manifest is wrong. A reader who follows rule 4 today will find ten files that fail and ten that cannot be checked, and will have no way to tell which failures are the 22 October sweep and which are something worse.

gen_manifest.py has a --check mode that exits 1 on any mismatch. It is not invoked by any workflow. grep -rn 'gen_manifest' .github/workflows/ returns nothing.

What broke. A manifest maintained by hand drifted from the tree it describes, and the tool that could have caught the drift was written but never wired up. The drift is not a single event: it accumulated across at least three sweeps over four weeks, and each sweep made it slightly worse.

What we learned. A verification mechanism that is not run is not a verification mechanism. The manifest's own docstring says the problem out loud — "It was maintained by hand, and by 2026-11-01 thirty-two of its 128 rows were wrong -- unchanged across four separate measurements, because nothing regenerated it and nothing checked it." That sentence was written by someone who understood the problem, and the fix they wrote was a --check mode, and the --check mode was not added to CI. The understanding was correct and the wiring was missing, which is the most common shape of a defect that survives.
