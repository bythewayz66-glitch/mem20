CStore / Recall Inspector

The trust surface. It makes the epistemic state of a memory explicit at the moment of writing, so simulation never silently becomes fact.

Wireframe C
answers O1 · O2

│  [ Store ]  [ Store as simulated ]  [ Cancel ]                │
├──────────────────────────────────────────────────────────────┤
│  AUDIT TRAIL (append-only)                                    │
│  14:02  store      grounded    by operator   ✓                │
│  14:05  recall     hit         query "qa"    ✓                │
│  14:06  feedback   relevant    +1            ✓                │
└──────────────────────────────────────────────────────────────┘
  • The rail is the product. Choosing grounded vs simulated is a first-class control, not a hidden flag.
  • Pre-store PII scan (memory_scan_pii) and dedupe run before write — governance at the point of capture.
  • Audit trail answers "what did the agent store?" (finding 10) and is described as append-only, never as tamper-proof.
  • "Store as simulated" gives the privacy/trust-conscious user a safe default for inferences.
