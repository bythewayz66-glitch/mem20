G3 serverInfo.version identifies the server build initialize returns "version":"" (empty string) misleads clients documented: do not assert on it
G4 Invalid tool names produce JSON-RPC -32601 no_such_tool_xyz ⇒ success response with isError:true, text Error: Unknown tool. Only unknown methods give -32601 misleads clients SDK treats isError as authoritative
G5 MCP resources/* and prompts/* usable initialize advertises only capabilities.tools; resources/list ⇒ -32601 doc drift SDK exposes the tool surface only
G6 A tool call returns its result 23 tools (all imagination_*, cog_*, tot_*, beam_search, least_to_most, react_reason, theory_of_mind_*, self_model_reflect, memory_auto_consolidate, cognitive_substrate) return {"job_id":…,"status":"running"} misleads clients call_tool_and_wait polls job_wait
G9 Required arguments are enforced ("required":["content"]) memory_store {} stores an empty fact and returns isError:false ⇒ success reported while nothing was indexed misleads clients SDK validates required args client-side (validation_error)
G9b isError signals handler failure A handler exception returns plain text with isError:false: Error recalling memory: slice indices must be integers… misleads clients SDK adds a text_error flag
Most load-bearing for a Perl client: transport framing (NDJSON, not Content-Length), the cwd = …/mcp requirement, and the fact that isError — not a JSON-RPC error object — is the authoritative tool-failure signal. G1 is what stops the server booting at all.
