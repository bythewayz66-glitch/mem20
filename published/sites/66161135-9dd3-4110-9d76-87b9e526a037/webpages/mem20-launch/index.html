mem20 is an MIT-licensed MCP server that gives AI agents persistent memory with a hard partition between grounded and simulated content, contamination auditing, an evidence-gated promotion path, and an append-only origin-tagged ledger.

Three things, and why they matter together

Every other agent-memory layer competes on retrieval quality. This one is built so you can answer a different question: what does this agent actually know, and where did it learn it?

Prove it, don't just retrieve it

Grounded and simulated memory are separate stores — not one store with a flag. Every ledger entry carries its origin and store, so "where did this come from?" is a query rather than a guess.

Catch contamination before it ships

Attempt a grounded write with invented content and the server raises instead of quietly succeeding. The audit reports a contamination rate for your store and names which violation class fired.

Own your memory layer

MIT licensed, Python, self-hosted. No PyPI package to trust and no vendor holding your audit trail — if the memory layer is what you must audit, you can't audit a black box.

How the partition works

The boundary is enforced on the write path, not asked for in a prompt. This is a real capture — it is the exact exception the shipped server raises.

 partition check · HEAD c274404
# grounded write — accepted
>>> remember("mem20-identity", "mem20 is MIT licensed.")
{'id': '1a13b4b8ea2f3bf', 'origin': 'grounded', 'store': 'grounded',
 'action': 'remember'}

# push invented content down the grounded path — REFUSED
>>> remember("mem20-hypothetical", "...", _allow_simulated=True)
PermissionError: remember() is grounded-only. Simulated content must use
remember_simulated(); this call is refused to protect Step 7.4 separation.

# simulated content takes its own path, into its own store
>>> remember_simulated("mem20-hypothetical", "Show HN hits #1 for six hours.")
{'origin': 'simulated', 'store': 'simulated',
 'epistemic_status': 'imagined', 'action': 'simulate'}

# recall() returns grounded only, unless you explicitly ask
>>> recall("mem20")                        → 1 result, origins ['grounded']
>>> recall("mem20", include_simulated=True)  → 2 results, origins ['grounded','simulated']

The three tiers

TierWhat lives hereHow it is enforced
GroundedFacts from real observations, user statements, eventsIndexes are grounded-only; writes to the vector and BM25 paths assert grounded origin
SimulatedHypotheticals, counterfactuals, model output — epistemic_status: imaginedSeparate store that is never indexed into the grounded path
PromotionSimulated content graduating to groundedEvidence gate — a linked prior prediction resolved in its favour, or a registered external verifier

The three violation classes the audit checks at this commit: violations_origin_not_grounded, violations_simulated_in_grounded_index, violations_simulated_in_bm25_corpus. All empty on a clean store.

A clean store reporting 0.0 is a captured audit output, not a published retrieval benchmark. We are explicit about the difference.

The promotion gate — all four paths, including the one we'd rather you didn't have to ask about

CallResultVerdict
Bare promote(sim_id)PermissionError: requires explicit external confirmation OR real-world prediction-error resolutionrefused
Prediction-error boolean onlyPermissionError: requires structured evidence linking to a recorded prior predictionrefused
Structured evidence, unrecorded prediction_refPermissionError: prediction_ref is not a recorded prior predictionrefused
Free-text confirmation alonepromoted: true — the gate accepts a self-attested string herePROMOTES — open path

So the gate is narrowed, not closed, and we say so. Three of four paths are refused outright; the prediction-error path now demands a real recorded prediction rather than a boolean. A free-text confirmation argument still promotes — closing that is the next piece of work.

We publish this table rather than describe the gate as airtight. A reader who tests it will find exactly what is written here.

What we do not claim

This section exists because the previous version of this page carried numbers the repository cannot reproduce. Here is the corrected position.

  • No LoCoMo, LongMemEval or DMR result. There is no benchmarks/ directory in the canonical repo at this commit and no retrieval hit-rate figure anywhere in the tree. We are not claiming parity with Mem0, Zep or Letta — and we are not publishing a table we cannot reproduce from a clone.
  • No "0.0 leak rate" headline. What exists is the live audit output above — contamination_rate 0.0 on a clean store. That is a property of a clean store, not a benchmark score.
  • No "tamper-proof" or "unfakeable" claim. The ledger is append-only and origin-tagged; the promotion gate still has the residual path documented above.
  • No PyPI package. pip install mem20 will not work. Install is from source.

Install from source

Not on PyPI yet. Clone, install, point any MCP host at it.

 bash
git clone https://github.com/bythewayz66-glitch/mem20.git
cd mem20

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# run the MCP server over stdio
MEM20_STORE_PATH=~/.mem20/store .venv/bin/python mcp/mcp_server.py

# health / readiness / metrics once the service is up
curl http://localhost:8080/health
curl http://localhost:8080/metrics   # tool counters + contamination_rate

Optional Blender and Unity integrations ship as separate pluggable modules and require the respective application installed. When absent, their tools return an informative message instead of failing.
