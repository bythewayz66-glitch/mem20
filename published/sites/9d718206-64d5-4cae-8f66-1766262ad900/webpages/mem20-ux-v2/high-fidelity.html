High-fidelity design — tokens plus the three load-bearing screens

The v2 hi-fi pass defines a real token set (type, colour, space, states) with contrast ratios verified against WCAG AA, then renders the three screens that carry the product's entire differentiator: the audit ledger, the partition view, and the memory inspector. The visual system is dark-first because this is an operator tool that sits open beside a terminal, but every colour decision encodes meaning rather than decoration — green means grounded, blue means simulated, amber means promoted / caution, red means broken.

Accessibility rule baked into the design: partition state is never communicated by colour alone. Every colour-coded element carries a text label (GROUNDED / SIMULATED / PROMOTED) and, where it is a count or a status, a distinct shape or position. This is the WCAG 1.4.1 requirement, and it independently helps P4 — an auditor reading a print-out or a projector must still see the partition.

Promotion gate — the only bridge
A simulated record may cross into grounded only through evidence-based promotion. Each crossing writes an event to the append-only ledger with its evidence attached.
⚠ Known limitation, disclosed in-flow: user-asserted evidence can satisfy the gate. Described as “evidence-based with an append-only audit trail” — never tamper-proof, never provably secure.
The single most important screenIt is the wedge made visible. P4 can point at it; P2 can put it on a projector.
Symmetry is the messageThe two panes are equal in weight so "hard partition" reads as structure, not as a filter or a preference.
Honesty as UIThe gate's known limitation is rendered on the gate itself, not buried in docs. Disclosed weakness is survivable.
