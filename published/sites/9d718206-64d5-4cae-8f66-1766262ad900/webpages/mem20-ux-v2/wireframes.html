Wireframes — six screens, auditability-first

Low-fidelity structure for the mem20 desktop app. Grey blocks are placeholders, not final styling — the point at this stage is information architecture and which surface owns which job. Two deliberate IA decisions drive every screen below: (1) the audit ledger is the home surface, because that is the product's differentiator and P4's only entry point; (2) the partition (grounded vs simulated) is a persistent, always-visible status, never a buried setting.

Rejected alternative: a "chat with your memory" home surface. It demos well but it hides the differentiator behind a conversational layer and gives P4 nothing to point at. The ledger-first IA is chosen precisely because the wedge is provable memory, and a proof needs a surface.

STATESStates every wireframe must cover before hi-fi

Empty

First-run ledger with zero events — must explain what will appear here and why it is empty, not just render a blank table.

Loading

Store read in progress. Never a bare spinner over an audit surface — show which read is in flight.

Degraded

Repo unreachable / version unknown / integrity not verifiable. This state is live today, so it is a first-class state rather than an edge case.

Error

Failed clone, failed wiring, failed smoke test — each with the exact command and the exact failure text.
