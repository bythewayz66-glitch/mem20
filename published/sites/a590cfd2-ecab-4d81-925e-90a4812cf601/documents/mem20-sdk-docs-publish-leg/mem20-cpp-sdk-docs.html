5 How the SDK speaks the protocol

MCP handshake, then discovery, then invocation — one JSON-RPC 2.0 frame per line on stdio.

spawn mcp_server.py→ initialize→ notifications/initialized→ tools/list→ tools/call
Request frame
{ "jsonrpc": "2.0", "id": 1,
  "method": "tools/call",
  "params": {
    "name": "memory_store",
    "arguments": {
      "content": "hello",
      "category": "general",
      "tags": "demo"
    }
  } }
Response frame
{ "jsonrpc": "2.0", "id": 1,
  "result": {
    "content": [
      { "type": "text",
        "text": "Stored memory with ID <id>" }
    ],
    "isError": false
  } }
  • No Content-Length framing — one complete JSON message per line, UTF-8, newline-terminated.
  • protocolVersion is negotiated in initialize and echoed from the server — never hard-coded by the SDK.
  • Tool refusals are results, not protocol errors — the server sets isError or returns text beginning VETO / BLOCKED / Error:, which the SDK surfaces via is_error().
  • The :8080 endpoints are observability, not part of the MCP session.

6 Partition & ledger rules encoded in the types

The mem20 invariants are mirrored in the SDK’s compile-time surface, not enforced by convention.

mem20 invariantHow the SDK expresses it
Grounded vs simulated is a hard partitionDistinct GroundedMemory / SimulatedMemory types map to different tools (memory_store vs memory_simulate_store); no overload accepts the wrong one
Promotion requires evidenceSession::promote(PromotionRequest) needs a non-empty confirmation or resolved_via_prediction_error + resolution_note; a refusal returns refused = true
Ledger is append-only, origin-taggedread_ledger() is const and returns value copies; no delete/update/erase API exists anywhere in the headers
Simulated content never enters grounded indexesmemory_recall binds the grounded-only indexes; list_simulated() is a separate call
Promotion is described exactly as “evidence-based with an append-only audit trail.” It is not described using security-guarantee wording — the audit trail makes provenance reviewable, not unforgeable.

7 Build, install & run

Exact commands documented in the SDK README, verified against the repo layout.

# 1 — get the server
git clone https://github.com/bythewayz66-glitch/mem20.git
cd mem20 && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# 2 — build the C++ SDK + example
cmake -S sdk/cpp -B build/cpp -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/cpp && ctest --test-dir build/cpp --output-on-failure

# 3 — store → recall → audit against the live server
MEM20_SERVER="$PWD/mcp/mcp_server.py" ./build/cpp/mem20_store_recall_audit

# install + export, so consumers can find_package()
cmake --install build/cpp --prefix /usr/local
#   find_package(mem20_sdk 0.1 REQUIRED)
#   target_link_libraries(app PRIVATE mem20::mem20_sdk)
The SDK adds no mandatory third-party dependency — it needs a C++ standard library only, so it drops into host-constrained builds. vcpkg/Conan coordinates are not claimed; use FetchContent pinned to a commit SHA for reproducible builds.
