08

Wiring & guardrails

To make sessions live

  • Point the launch-page analytics at the site's analytics endpoint for project f7c01331….
  • Group sessions by utm_source and utm_content — the query string is already on every tracked link.
  • Feed the per-channel figures into the Sessions column in section 05.

To make stars & clones live

  • Public repo metadata works with no token today — stars, forks and issues refresh hourly.
  • Clones and views need a read-only token on /traffic/clones.
  • If the repo is not yet public, the card reports that plainly instead of showing a number.

To make HN / PH rank live

  • HN points and comments come from the public Algolia API with no key.
  • Front-page rank has no public endpoint — it is read from the HN front page and entered manually.
  • Product Hunt needs an OAuth token; the launch is scheduled for Day 2 so it does not compete with HN.

Publish path — Sidney via gabe

  • The canonical publish target for mem20 assets is the Sidney server, pushed over ssh / sftp / rsync and passing through gabe.
  • No Sidney credentials exist in the analytics sandbox, so this dashboard publishes to its /sites/ URL and the Sidney push is carried by the publishing step.
  • Re-opening this dashboard with ?repo=owner/name re-points the repo card, the footer link and the live API call — no code change needed.

Guardrails held here

  • No LoCoMo or LongMemEval claim — mem20 has none comparable, so none is made.
  • Adversarial 0.000 is disclosed wherever these benchmarks appear.
  • Promotion is described as evidence-based with an append-only audit trail — no absolute-security framing.
  • No unqualified superlatives and no competitor put-downs; the category line is simply that rivals optimise retrieval while nobody leads with auditability.
