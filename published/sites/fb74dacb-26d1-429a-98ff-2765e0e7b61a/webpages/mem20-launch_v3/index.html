The wedge

Not a retrieval-quality race. A trust and provenance race.

Every memory layer on the market competes on retrieval quality. None of them lead with auditability — the ability to show why a memory is in the store and where it came from. In a regulated context that is the whole ballgame: you don't need "probably relevant," you need "here is the source, and here is the evidence it was promoted."

Prove it, don't just retrieve it.

A hard grounded/simulated partition plus an append-only origin-tagged ledger tells you where every memory came from.

Catch contamination before it ships.

Auditing detects simulated content bleeding into grounded memory — leak rate 0.000 on clean stores.

Own your memory layer.

How the partition works

Two memory classes, one gate, and a ledger that keeps the receipts.

Grounded and simulated memory are not the same store with a boolean flag. They are separate classes, so "the agent made this up" is structurally visible instead of silently plausible.

Grounded memory

What the agent actually knows

Content that traces to a real source. This is the only class a downstream decision should be allowed to rest on — and every entry carries its origin.

Simulated memory

What the agent generated

Hypotheses, drafts, inferences and speculative content the model produced. Useful, kept, and quarantined by construction — never silently indistinguishable from fact.

Evidence-based promotion — with an append-only audit trail

Nothing graduates from simulated to grounded by assertion. Content is promoted only with evidence attached to the promotion, and that promotion is recorded. The claim is auditable — an append-only trail you can inspect — not a claim of cryptographic tamper-proofing.

☰

Append-only, origin-tagged ledger

Every memory carries its source. History is written forward and tagged with origin, so the record can't be quietly rewritten after the fact — and an audit can reconstruct what the agent knew, and when.

Read this before you read the table

These benchmarks are self-published on our own harness. mem20 does not yet have a published LoCoMo or LongMemEval result comparable to Mem0 or Zep, so we make no parity claim and cite no one else's figure as ours.

The 0.000 adversarial hit rate is a genuine limitation, not a marketing footnote: an adversary who knows how to phrase around the retrieval path can defeat it today. If your threat model includes adversarial query injection, weigh that honestly.

Straight talk

What we don't claim.

Three limits we'd rather state ourselves than have someone else discover in production.

No LoCoMo / LongMemEval result

mem20 has no published benchmark comparable to Mem0 or Zep. We do not imply parity, and we never present their numbers as ours.

Adversarial hit rate is 0.000

Hard adversarial queries defeat the retrieval path today. It's on the roadmap, and it stays visible wherever the benchmark table appears.

The promotion gate has known gaps

A self-attestation hole in the promotion gate was flagged in a prior audit. Promotion is auditable, with an append-only trail — not unfakeable, and not cryptographic.

Install

Run it on your own infrastructure.

If your memory layer is the thing you have to audit, you can't audit someone else's black box. mem20 is MIT-licensed and self-hosted by design.

shell 
# clone and install from source
git clone https://github.com/bythewayz66-glitch/mem20.git
cd mem20
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# run the MCP server over stdio (JSON-RPC 2.0)
MEM20_STORE_PATH=~/.mem20/store .venv/bin/python mcp/mcp_server.py
